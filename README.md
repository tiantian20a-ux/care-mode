# 老年机关怀模式 · 第 1 步：通用安卓规则包

这一步做的是**所有安卓手机都能用**的部分，品牌专属的去广告（小米、OPPO、vivo 等自带的广告开关）放到第 3 步。

## 文件

| 文件 | 作用 |
|---|---|
| `rules/common.json` | 通用规则包，9 条规则 |
| `tools/plan.py` | 校验规则格式，并模拟一台手机打印出完整的「备份 → 执行 → 校验 → 还原」命令 |
| `tools/fake-devices/*.json` | 两台模拟手机：小米 Android 14 有网、OPPO Android 11 没网 |

试运行：`python3 tools/plan.py rules/common.json --device tools/fake-devices/xiaomi-sdk34.json`

## 9 条规则

| 规则 | 默认 | 做什么 | 能还原吗 |
|---|---|---|---|
| 调大字体 | ✅ | 字体 1.3 倍（Android 14 以上可选到 1.8 倍） | 能 |
| 调大显示 | 不勾 | 图标和按钮一起放大 1.15 倍 | 能 |
| 长按变慢 | ✅ | 长按要按 1 秒才生效，防止误拖、误删桌面图标 | 能 |
| 熄屏 5 分钟 | 不勾 | 屏幕 5 分钟没操作才熄灭 | 能 |
| 私人 DNS | ✅ | 用 AdGuard DNS 拦广告，可选家庭版（多拦成人、赌博网站） | 能，连不上会自动改回 |
| 禁止安装未知应用 | ✅ | 收回所有 App 的「安装未知应用」权限，应用商店照常 | 能 |
| 暂停快应用 | 需机主同意 | 用 `pm suspend` 暂停快应用，挡住广告里直接弹出来的页面 | 能，一条命令恢复 |
| 关营销通知 | ✅ | 只关名字带「推荐、活动、优惠、热搜」等的通知类别，验证码、天气、快递、支付类永远不碰 | 能（第 2 步实现） |
| 收尾：关开发者选项 | ✅ | 最后关掉开发者选项和 USB 调试 | 需重新打开 USB 调试 |

## 安全原则（参考 android-ad-cleaner）

1. **不卸载、不停用系统应用**，只改系统设置；暂停应用只用可恢复的 `pm suspend`。
2. **先只读检查**：确认是机主账户、手机能上网，不满足就跳过或停止。
3. **先备份再改**：每个设置的原值都记下来，备份文件要先存到电脑上，因为最后一步会断开连接。
4. **改完要校验**：DNS 设好后等 15 秒测一下能不能上网，不行就自动改回，避免老人手机突然断网。
5. **还原按倒序**：最后改的最先还原；原来没有的设置直接删掉，回到系统默认。

## 需要你知道的风险

- **AdGuard DNS 在国内不一定稳定。** 所以加了自动校验和回滚。真机测试时如果经常连不上，我们再换方案。
- **荣耀快应用包名 `com.hihonor.fastapp` 还没核实**，已标为未验证，真机测试时确认。其他 4 个品牌的包名比较常见。
- **关营销通知要靠界面自动化**，因为系统没有直接关某个通知类别的命令。这条规则已经写好，具体点击逻辑在第 2 步网页工具里做。
- 以上命令目前只在模拟手机上跑过，还没有在真机上验证，这是第 4 步的事。

# 第 2 步：网页工具（Chrome/Edge）

在电脑上的 Chrome 或 Edge 里打开网页，用数据线连上手机，按页面提示走四步：**打开 USB 调试 → 连接并检查 → 勾选要做的设置 → 下载备份后执行**。首页还有「从备份还原」和「先看演示（不用连手机）」。

## 怎么运行

```bash
npm install
npm test          # 引擎自动测试（模拟手机）
npm run dev       # 本地打开 http://localhost:5173 ，加 ?demo 进入演示模式
npm run build     # 打包成静态网页，输出到 dist/，可放到 GitHub Pages
```

WebUSB 只能在 https 或 localhost 下用，所以要么本地运行，要么部署到 GitHub Pages 这类 https 网站。

## 代码结构

| 文件 | 作用 |
|---|---|
| `src/engine.ts` | 规则引擎：检查、备份、执行、DNS 校验和自动回滚、从备份还原 |
| `src/channels.ts` | 营销通知：读取通知类别，打开系统设置页、找到开关点一下，再确认真的关掉了 |
| `src/adb-usb.ts` | 用 Tango 通过 WebUSB 连接手机 |
| `src/fake-phone.ts` | 模拟手机，用于自动测试和演示模式 |
| `src/main.ts` | 页面 |
| `src/ui.ts` | 界面自动化：读屏、找字、翻页、关开关、关弹窗（移植自 android-ad-cleaner） |
| `src/recipes/xiaomi.ts` | 小米配方：9 个应用里的广告开关 |
| `src/fake-ui.ts` | 模拟小米手机的设置页面，用于测试 |
| `test/*.test.ts` | 20 个自动测试 |
| `tools/e2e-demo.cjs` | 浏览器里走一遍演示模式的完整流程 |

## 安全设计

- 备份文件里只存结构化的原值，不存命令。还原前逐项校验，被改过的备份文件会被拒绝，不会在手机上执行任意命令。
- 「需机主同意」的项目必须额外勾选确认框才能执行。
- 必须确认「已保存备份」才能开始执行。
- 营销通知只在确认关掉后才算成功；锁屏或点错时会把开关点回去，并报告跳过。

## 已知限制

- 目前只在模拟手机上测过，还没有连过真机（第 4 步）。
- Windows 上如果装过手机助手或 adb，可能占用 USB，页面会提示关掉。

# 第 3 步：品牌专属规则

连上手机后，工具按品牌自动加载专属规则包，显示在「通用设置」下面。

## 小米 / 红米 / POCO（`rules/xiaomi.json`）

设置路径来自 android-ad-cleaner 在 Xiaomi 18 Pro Max（HyperOS OS4.0.24）和 18 Fold 上的实测清单。

| 规则 | 默认 | 做什么 |
|---|---|---|
| 暂停系统广告组件 msa | 需机主同意 | 暂停 `com.miui.systemAdSolution` 并禁止它联网。它负责天气、日历、商店的开屏和内置广告。可一键恢复 |
| 系统广告服务 | ✅ | 关个性化广告推荐，打开「限制广告跟踪」 |
| 应用商店 | ✅ | 关个性化服务、新手帮助推送；保留应用更新、推送消息 |
| 手机管家 | ✅ | 关个性化推荐、清理后的推荐内容 |
| 下载管理 | ✅ | 关资源推荐、热榜推荐 |
| 主题 | ✅ | 关联网通知、个性化推荐；保留自动更新 |
| 浏览器 | ✅ | 关个性化内容/广告推荐、宫格位推送、猜你想搜、小说；主页样式不改 |
| 桌面搜索 | ✅ | 关搜索提示词、推荐未安装应用、各类热搜榜；保留常用应用 |
| 负一屏 | ✅ | 关推荐卡片、热门活动；保留搜索框、出行助手 |
| 天气和日历 | ✅ | 关内容推广、天气视频卡片；保留天气预警 |

**怎么做到的**：工具自动打开每个应用，读屏找到设置入口和开关，点掉广告类开关，再读屏核对。新旧版应用的入口都兼容，找不到就跳过，不乱点。打开时弹出的更新框会点「以后再说」，权限申请只点「拒绝」。

**还原**：msa 能自动还原。应用里的开关没法安全地自动拨回，执行后备份文件会记下每一个改动和手动还原方法，页面会提示再下载一次完整备份。

**注意**：小米必须在开发者选项里打开「USB 调试（安全设置）」（要插 SIM 卡、登录小米账号），否则电脑点不动屏幕，这些项目会自动跳过。

**限制**：只在模拟手机上测过。原版会识别自己画的开关（靠截图看颜色），网页版暂时不支持，这类开关会跳过。每次读屏要 1～2 秒，全部做完大约 5～15 分钟。

# 第 4 步准备：真机测试工具

还没有真机时先把排查工具做好，拿到手机后能少跑几趟。

## 各品牌打开 USB 调试的指引

第一步页面上先选手机品牌，显示这个品牌「连点 7 次」和「开发者选项」的位置，以及要打开哪几个开关（小米要多开「USB 调试（安全设置）」，荣耀和华为要开「仅充电模式下允许 ADB 调试」）。内容在 `src/guide.ts`。

## 再次设置同一台手机

备份里记了手机的匿名编号（android_id 的哈希，不存原值）。同一台电脑上再次设置同一台手机时，新备份会自动合并上一次的备份：同一项以第一次设置前的原值为准，只在上次改过的项也会保留。这样用最新那份备份就能还原到最初的样子。还原成功后浏览器里存的那份会被清掉，下次不再合并。

## 只检查，不改设置

选设置的页面上有「只检查，不改设置」按钮。它会照常打开每个设置页、找到要改的开关，但**一个都不点**，单选项（简洁首页、不显示等）和「全部关闭」也只看有没有、不点。最后列出每一项「会改几个、几处没找到」。适合在新机型、别人的手机上先试一遍。检查完 USB 调试还开着，需要手动关。

## 诊断文件

正式设置后如果有入口没找到，或者用了「只检查」，页面会提供「下载诊断文件」（`care-mode-diagnostics-*.json`），里面有：

- 手机型号、安卓版本和各家系统版本号（HyperOS、ColorOS、OriginOS、MagicOS、EMUI、One UI 的版本属性）
- 每一项的结果和完整日志
- 每次没找到入口或开关时的屏幕内容（压缩成每行一个控件：位置、类名、文字、开关状态）和当时前台应用的版本号；「只检查」还会记下每个检查过的页面

屏幕文字里可能有账号昵称，发给别人前可以先打开看一眼。拿到诊断文件后，对照 `screen` 里的文字改 `src/recipes/` 里的入口名即可。
